# 公共测试接口与验收草案

状态：待用户确认 S1—S5；本轮未写测试、未实施、未运行模型实验。

沿用已接受的任务装配、prepare/invoke、工具往返、运行入口和独立 score_task/summarize 五类职责。新协议只增加必要方法行为；不重新验收清洗或打开通用渠道修复。命名为拟议公开接口，确认后固定，不以私有 helper 为测试 seam。

## S1 任务准备与候选

拟议接口：`macrec_experiment.prepare(source_manifest, scope, configuration)`；命令行 prepare 只准备，不能自动发送。

捕获：开发/测试隔离、历史/候选/对象绑定、共同 D、信息权限、无发送准备。不能证明：模型语义质量、统计收益。

验收：

- 只消费接受版本及确认开发范围；原分组、100 测试名单/结果、原 C 不改变。
- 相同 H/目录/请求但替换私有目标、目标文本/评分、参考状态，模型可见包及所有准备请求逐字节一致；没有 `gt_answer` 或含目标样本对象。
- 同一个输入给 B0/I1/消融产生同 C/D/b 和顺序；目标不在 D 时仍不补入；未召回用户不被删掉。
- 三路内容分、RRF 和 tie-break 用独立手算小样例验证；开发参数选择有全量候选/所有试过配置记录，运行时不读取评价结果。
- prepare 不读凭据、不创建发送意图、不调用计数或模型端点；外部网络/凭据/评价路径访问被测试守卫拒绝。

## S2 单根推荐与反馈

拟议接口：`macrec_recommendation.run_task(task, *, method, invoke, evidence, policy)`；返回方法真实 ID、终态、源引用、全部 D 的得分/排列、前后版本和收据引用。invoke 是模型外部接口替身；本地算法/生产证据模块保持真实。

捕获：真实协作控制流、排序输入如何产生输出、反馈干预和终止。不能证明：真实 LLM 是否总能理解文字、是否提升偏好指标；这由后续开发运行观察。

验收：

- B0 的 Manager 动作可选择分析/检索，观察进入后续决策；Reflector 读前一 trial 并能影响第二 trial；不将按顺序六次画像通过为 B0。
- B0 排列只校验完整 D/去重/成员资格。换成任何合法私有目标不改变解析反馈或后续轨迹。
- I1 对同来源候选的语义匹配能改变实际得分与 Top-K；每个 D 候选有完整匹配行或明确 unknown。用独立设计的候选对、可见引用及预定名次验证，不用实现复算自身期望值。
- 当前明确偏好优先；仅标题出现不能形成确定偏好。重复角色/重复句子不能增加历史父商品数；一条历史的 c 小于多个独立父商品的相同倾向；有矛盾时收缩；无引用、零维或 c=0 时回退共同 b。
- q 下降时该维调整向 b 收缩，q=0 不新增匹配贡献。没有材料或对象错配不能变成高分事实；必要条件未支持不能因分高发布。
- 定位反馈纠正一项可见错引/匹配后实际重排并保留旧版；无问题不强迫变化；A-feedback 返回真正前缀，不能带入反馈后的 w/m/引用。
- A-semantic/A-confidence/A-quality 变化会使受影响下游重新处理；只改公式后复用旧反馈的做法不能作为完整消融。
- 同一根超过四步/trial、三次调度/trial、三个内部生成/调度或两 trial 时，以明确终态停止；相同公开资源限额适用于 B0/I1。

## S3 证据工具往返与缓存语义

继承公开接口：`EvidenceSession.dispatch(...)`、`assess_current()` 及现有质量核验公开入口；只在新运行器接线，不改既有四态/库存规则。

捕获：真实工具来源、对象/版本/权限、缓存失效对排序输入的影响。不能证明：SIM 等于现实供应链、Fabric 已存在。

验收：

- list/read/assessment 的实际返回而非私有参考进入决策；分页/原文范围不完整不能判 Supported。
- 保留 parent—batch—event—claim—version；错配、过期、撤销、冲突沿既有用例保持原状态。
- 变快照、时点、权限、材料值或引用版本后，受影响的资格、q、候选比较/反馈重新处理；纯 H 画像可继续复用。
- 无关材料改变不增加独立证据数、不污染不相关候选；相同材料只有实际摘要与权限等绑定相同才可共享。
- 反事实差异通过预置公开夹具验证，不重生成/清洗真实数据，也不把旧批量验收当本次在线模型轨迹。

## S4 开发运行与持久账

拟议接口：`macrec_experiment.execute(plan, *, invoke, clock)` 以及对应显式启动 CLI；计划与确认绑定，不改旧 compact 的输出常量或授权文件。

捕获：意图/收据、单次发送、恢复、预算、失败/未决、禁止旧路径写入。不能证明：供应商计费准确性、一天一定完成。

验收：

- 未确认开发配置不能启动；不会因继承旧任务授权而越过新方案。代码/提示/参数/来源任一摘要改变拒绝旧执行绑定。
- 发送前持久化意图，所有状态计入账；已成功/失败/未决请求不会恢复重发；SDK 零隐藏重试。
- 两在途仍由一个协调者登记，原子扣减全轮余额，不能重复认领同槽；等待、失败、测试/评价和临时文件不绕过预算。
- 24h、10GiB、调用额度均预留再派发；到第 22h 不再派新模型任务；收口写入仍受总限。超时、连续错误等按预算文档停止。
- 新输出仅位于独立 `data/recommendation-runtime-audit/macrec-agri-dev-<configuration_id>/`；旧代码、原文、研究、100 用户结果及原账摘要不变。
- 真实接口仅沿用当前模型/渠道，所有 effort/额度写入请求与账；请求不完整/超限失败保持，不能自动降档或加额。

## S5 独立评分与结果解释

拟议接口：`macrec_evaluation.score_task(task, observed, reference)`、`summarize(plan, scores)`。评价代码不导入推荐排序/生产资格计算生成真值，无供应商能力；复用已接受参考关联与 HR/NDCG/SJ 定义。原旧协议 scorer 与历史结果不修改。

捕获：全部用户分母、召回缺失、失败/NA、场景聚合与方法真实标识。不能证明：独立自然人、无暴露新测试或统计充分性。

验收：

- 手工列表中命中第 1/2/11 位、目标未入 D、终结失败分别与独立常量或数学定义一致；旧 R/S/M 接口样例在新适配指标上同值。
- B0/I1/消融保留原真实 ID；C 与参考仍完整，不能把 D 伪装成 C 提高理想增益或剔除漏召回。
- 全体用户的端到端 HR/NDCG 和 Recall@M 同时可得；另外的成功/召回子集不覆盖主表。目标参考不合格的 SJ 为 NA 并报人数；真实偏好指标仍单列。
- `retrieval_empty` 不等于全 C 无合格项；失败=0，未启动/未决/流水线错误保持各自状态，不伪造完成。
- 场景先在用户内汇总，bootstrap 以用户重采样；开发调参结果和暴露说明在报告中。四消融给全部指定场景、人数与区间，不择优 K。
- 汇总能从实际任务、引用和收据独立重算；单价与失败 usage 未知保持 null/unknown。
