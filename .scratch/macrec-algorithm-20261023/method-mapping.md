# 原方法 领域适配与新增改进对应

状态：待确认草案。源码固定为作者仓库 `wzf2000/MACRec` 的 `cbd9ea036cf6cac05a2ee59592526982a626fc82`，论文固定为 arXiv:2402.15235v3。完整永久链接与逐行证据见[原始来源研究笔记](../../research/MACRec原文与源码固定核查_20261023.md)。这个提交是本次可用版本，不冒称 2024 年发表时版本。

## 1 三层对应

| 环节 | MACRec 原文与固定源码 | 两个主方法共同采用的农产品适配 B0 | 本文拟新增的 I1；效果尚待检验 |
| --- | --- | --- | --- |
| 管理协作 | Manager 按 Thought、Action、Observation 循环选择 Analyse / Search / Finish；每步 Thought 和 Action 是两次生成 | 保留决策、工具往返、观察回流和任务终止；在同一个候选排序任务中运行；用既有 Responses 发送器替换作者模型 wrapper | 管理者调度带来源的候选偏好比较，提交可验证的属性/匹配修订；程序由这些决策复算排名 |
| 用户分析 | Analyst 经 Info / History 工具分析用户；User/Item 共用一个类，由动作参数区分 | 用户画像角色只读冻结的较早历史；以明确历史截断替换作者含目标的 data_sample 定位 | 提取明确喜好、抱怨及未知；按不同历史父商品数和矛盾情况收缩偏好置信度，避免一条标题被当成稳定喜好 |
| 商品分析 | Item Analyst 分析所询商品属性；SR 中可选 | 农产品画像角色读取共同召回候选及白名单 title/crop；允许比较候选，禁止推造产地、认证、实物质量 | 对候选—偏好逐项给出语义匹配、来源字段和证据定位；匹配进入确定性排序，脱离有限标题词的精确等值限制 |
| 检索 | Searcher 按管理者要求 Search / Lookup / Finish，作者工具是 Wikipedia | 用既有受限证据接口替代外网事实搜索；查询对象、批次、快照、时间、权限保持绑定；生产核验器沿用 | 生命周期角色返回缺口、适用状态及可读质量分量；管理者据此检查相关候选，低质量证据只支持有限的排序调整 |
| 反思 | Reflector 在下一次完整 trial 之前审阅上轮轨迹；可自评通过而早停 | 推荐依据核验承接该入口，最多一次反思、两次 trial；仅允许格式、来源和当前任务约束反馈 | 反馈定位候选、偏好、主张和引用；可使错误匹配、置信度或引用被修订，并触发重新计算最终排名 |
| 需求解释 | Task Interpreter 将输入/对话转换为任务；论文 SR 配置并非必选 | 保留需求解析角色；把既有结构化实验请求与历史推断分开，当前明确请求优先；不模拟用户新反馈 | 明确偏好与推断偏好的置信度处理不同；不给不存在的用户需求赋值 |
| 候选 | 作者脚本为 7 个随机负项加 1 个目标；不是召回任务 | 完整 C 为既有 1,494 商品目录剔除本用户已见商品，并关联唯一 SIM 批次；旧 100 人 C 为 1,489—1,493，开发实际规模逐根报告。共同内容召回产生 D⊆C；不接触目标、不补目标 | I1 仅在同一个 D 上优化排序；与 B0 的召回完全一致，不把召回变化冒充精排改进 |
| 输出合法性 | 固定源码 ranking parser 利用 GT 是否在输出中判断合法，并未完整验证排列 | 必须改为只验 D 的成员、数量、唯一性与完整排列；不把 GT 传入运行对象；终结资格沿用既有生产门禁 | 新增语义匹配/反馈输出也必须可追溯，不能以模型自评绕过门禁 |
| 最终排序 | Manager 给出给定候选排列 | B0 按 Manager 排列取通过共同资格门禁的 Top-K，不接入 I1 的置信度与质量融合公式 | I1 用共同内容分作先验，并融合经过来源检查的匹配、置信度和证据质量；管理者不能直接改写程序分数 |
| 信息与运行约束 | 作者默认 gpt-3.5、10 个管理步，子代理可有多轮内部调用；无统一总账 | 两主方法均沿用 4Router / gpt-6-luna，同样最多 4 管理步/trial、3 次子代理调度/trial、3 次内部生成/调度、2 trial；统一缓存、失败与总预算 | 算法成败不由角色数或调用数衡量。预算变化必须先披露，不能悄悄提高 I1 的额度 |

命名：`B0=MACRec-Agri-bounded-v1` 表示**固定版本机制的农产品适配移植**；`I1=Agri-EvidenceRank-v1` 表示拟议改进。未运行作者默认环境、未复现其演示数值；原文本身没有 HR/NDCG 量化对照表。不得把 B0 写成作者代码零修改复现，也不得将当前 compact M 改名为 B0。

## 2 六角色的可观察责任

下表列 I1 的最小输出合同。B0 拥有相同原始数据与工具权限，但 Analyst 保留通用分析和 Manager 排列，不额外赠予 I1 已生成的匹配矩阵、置信度或融合排序结果。

| 本文角色 ← MACRec 对应 | 输入与可访问范围 | 必须产生的输出 | 如何影响最终排序 |
| --- | --- | --- | --- |
| 需求解析 ← Task Interpreter | 根任务当前请求；请求来源；H 仅用于区分推断，不允许从历史生成新的必要条件 | `necessary`、`explicit_preferences`、`inferred_aspects`、`unknown`，逐项绑定请求或历史来源 | 必要条件交给共同门禁；明确偏好覆盖同维历史推断；确定可参与匹配的维度 |
| 用户画像 ← User Analyst | 本用户严格较早的文本、评分、历史父商品 title/crop；需求解析结果 | 不超过 6 个偏好维度、正负倾向、权重建议、原文跨度、支持/矛盾的历史父商品集合；未支持项为 unknown | 程序验证引用，计算权重与 c；短历史及矛盾降低对内容先验的调整幅度 |
| 农产品画像 ← Item Analyst | D 全部候选白名单属性、用户已获准偏好、可访问的当前证据观察 | 每个候选—偏好的 `match∈{0,.25,.5,.75,1}` 或 unknown；属性来源、原文跨度、解释；不得缺行后默认高分 | 已验证的 m 直接进入排序；标题隐含或无法观察的属性保留 unknown |
| 生命周期追溯 ← Searcher | 管理者提出的候选/主张查询，固定快照、时点与权限；经 list/read/assessment 的实际返回 | 批次、事件路径、四态、接受/拒绝引用、缺口、库存质量分量的来源；建议查询只指向已允许材料 | 生产门禁确定资格；有支持的软属性形成 q 和 m；模型不能自填材料、q 或把缺失改成支持 |
| 推荐管理 ← Manager | 共同内容分 b、分析输出、当前材料、初稿排名、预算与核验反馈 | 子任务动作；候选比较（尤其前十边界）；带理由的属性/匹配修订提案；提交核验 | I1 的提案经验证后改变 m/c/可用维度并由程序重排；B0 则给出候选完整排列 |
| 推荐依据核验 ← Reflector | 当前排序、被采用的偏好与匹配、引用及允许原文、上轮轨迹；看不到目标或指标 | 问题定位 `candidate/aspect/claim/ref`，原值与建议修订、证据；或无可修订问题 | 有依据的问题回到下一 trial；移除不支持的推断、纠正匹配或补读允许材料，实际重算；无反馈消融保留其前缀输出与程序门禁 |

最多 6 维是本次工程上限，不声称六维最优；两方法原始信息一致，B0 不被限制只能读取这些六维摘要。重复角色引用同一历史或同一材料不增加独立支持数。

## 3 保留机制与领域扩展的边界

- 原论文 SR 表格必选 User Analyst、Reflector，Item Analyst 可选；Searcher/Interpreter 并非该表的固定 SR 组合。选择具备这两类扩展角色的作者配置并映射六角色，是本项目适配，不是对原论文固定六角色的复述。
- 作者 Evaluate 的反思记录存在静态继承断言不一致。本项目移植经审计的控制流，沿用现有独立评价；不修复或部署整套作者依赖，也不将静态阅读写成已跑通。
- 限制内部轮数、替换数据集与模型、屏蔽 GT、加入共同资格门禁、加入缓存，均记入 B0 与 I1 的共同适配清单。报告须列出截断/耗尽频率，防止只在基线频繁耗尽时宣称算法优势。
- 生命周期事实仍是 SIM；目录标题只是来源字段或商家文本，不能被升级成真实检验结论。自然语言共识不产生新事实。

当前 compact R/S/M 的调用模式与既有结果继续保留，它们只作为辅助对照和历史事实。新方法是否有效，由新开发对照的固定分母 HR/NDCG 判定。
