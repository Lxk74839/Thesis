### 4.2 强内容辅助基线 CB

CB 使用同样 H 和目录，形成三个词法视角：既有 char3 TF-IDF、word unigram/bigram TF-IDF、BM25。目录拟合 IDF/长度统计；历史文本、关联 title/crop 按既有 rating/5 聚合查询；不使用留出交互或全局评价用户评论。分词固定 Unicode NFKC/casefold，英文词/数字；不新增人工目标词表、品牌偏置或伪造属性。

BM25 固定 `k1=1.2,b=.75`；三路按加权 RRF，常数 60。权重仅比较 `(1,1,1)、(2,1,1)、(1,1,2)` 三组，顺序为 char/word/BM25；在完整开发 320 人的 V00 NDCG@10 上选择，HR@10 次级，同分按所列顺序。最终分在完整 C 最小—最大归一化，同分取 .5。三路单独成绩同时报告，不能仅报告胜者。RRF 的定义参见[作者原论文](https://cormack.uwaterloo.ca/cormack/cormacksigir09-rrf.pdf)；本项目不继承其在其他数据上的增益结论。

实现口径固定：商品文档为 `title + 空格 + crop`，历史查询文档为 `text + 空格 + 历史 title + 空格 + crop`；char 路直接使用接受包的既有完整 C 分数，不重定义旧计算。word 路 IDF 为 `log((1+N)/(1+df))+1`，原始词频×IDF 后每个文档 L2 归一化，各历史向量按 rating/5 求和再 L2 归一化，与商品向量取余弦。BM25 只用 unigram，`idf=log(1+(N-df+.5)/(df+.5))`，查询词权为各历史 `(rating/5)×该词频/该历史词数` 之和；对商品词频采用标准 `tf×(k1+1)/(tf+k1×(1-b+b×len/avglen))`，按查询词权求和。词表/df/平均长度只在允许目录拟合；不在词表的查询项无贡献。三路原始分 round12 后同分用平均名次，RRF 为 `Σ_j weight_j/(60+rank_j)`，不以 ID 顺序打破词法同分再产生虚假强弱；最终同分才按商品 ID。空查询或所有路均无区分时 b=.5。

CB 在完整 C 输出 Top-K，作为强词法内容辅助基线；另报裁至共同 D 后的同方法，帮助识别精排增量。其强度由实际完整开发成绩审视，不能预先承诺压过现有 R。

### 4.3 共同 D 与覆盖

先在完整 C 计算共同 CB 分 b，再取 Top-M 为 D；两个主方法与其消融使用完全相同 D、b、候选输入顺序和源快照。只在开发 320 的评价侧检查 `M∈{50,100,200}` 的目标覆盖，选最小达到 .90 的 M；均未达到则固定 200，报告实际上限及未达到事实，不补入目标。这个 .90 是本次工程选择规则，不是数据充分性证明。

模型侧只接收 D 和允许源，不接收命中标记、目标覆盖或“这是正例”等反馈。输入顺序由 root ID 和固定域字符串的哈希排序决定，与目标无关；两主方法相同。不因某用户目标未召回而丢掉用户。

最终推荐只从 D 内按各自方法及共同资格门禁取得，不能从 D 外补足十项。根任务仍保留完整 C 绑定，评价理想增益仍基于完整 C。若 D 无合格项但 C 有，记为 `retrieval_empty`、偏好指标为 0，不能冒称完整 C 无合格候选。报告：完整 C 规模、M、Recall@M、参考合格目标的覆盖、最终端到端 HR/NDCG（固定全部用户分母）；“仅召回命中用户精排分数”最多作为单列条件分析。

## 5 两个主方法与排序算法

### 5.1 B0 的可执行控制流

移植审计后的 MACRec 控制流，使用已有公共发送器、获准历史/目录工具和 EvidenceSession。原作者环境/依赖不安装，上游快照只读。

每 trial 最多四个 Manager 步；每步保留两次生成（Thought、Action）及 Observation。每 trial 最多三次 Analyse/Search 调度，每次子代理最多三个内部生成命令（包括 Finish）。因此可读取资料/历史、完成分析，也有明确耗尽状态。配置六角色，Manager 可按当前任务选择分析与检索，并非每次强制六角色逐一输出画像。需求解析每 trial 最多一次。

第一 trial 提交 D 的完整、无重复排列；宿主只验允许集合，不读 GT。第二 trial 开始前 Reflector 最多一次，依据输入、轨迹和允许事实反思；无可修订问题则保留原答案，否则带反馈再次求解。Reflector 自评是自检，不能称已知命中与否。最终从 Manager 排列中过滤共同门禁不合格项并取 K，保存过滤前排列与最终输出。

GT 依赖的合法性反馈、以目标定位历史、作者候选拼目标，必须全部移除并测试。预算缩减、同模型、缓存和领域门禁都是共同适配，不列为本文性能创新。原默认轮数下的完整作者运行不在本轮复现范围内；如果 B0 大量耗尽，应报告适配预算局限，不能只凭 I1 胜出推断原 MACRec 较差。

### 5.2 I1 的有来源偏好与语义匹配

I1 使用同样的控制框架和每根上限。第一 trial 中用户画像、农产品画像和生命周期观察须实际进入候选比较，缺少相应结果不能标完整 I1。最多六个偏好维度，当前明确要求优先；历史既可有正向喜好，也可有对属性的抱怨，不能因整条评分为正就把所有标题词当喜好。

每维给出非负权重建议，宿主验证有限/总量正后归一化为 w；空画像直接使用 b，不计算不存在的归一化分母。仅有标题出现、泛泛赞誉或无法定位的推断不形成确定偏好。模型可做语义映射，例如有明确来源的“rolled oats”与候选“oat flakes”之间的形态匹配；不能推出未知口味、认证或批次属性。

每个 i∈D、维度 d 给出匹配 m∈{0,.25,.5,.75,1} 或 unknown，需同时引用偏好源与候选属性源。负向偏好以“不具有所排斥属性”的可观察匹配表达，无法观察不能默认满足。所有候选都须有该维记录或明确 unknown，不能只分析初始前十再把它当 D 的排序。

### 5.3 短历史置信度

当前明确请求的偏好取 c=1。历史偏好以不同父商品去重，每商品每维至多计一次；同一评论多句或多个角色重复引用不增加支持。

对同一属性及目标值的直接偏好语句，先在父商品内合并；同一父商品内部不能解决的矛盾标未知，不重复算入两侧。令 n+ / n− 为不同历史父商品中该偏好的相反倾向数量，n=n++n−，`a=|n+−n−|/(n++n−)`，`c=n/(n+τ)×a`。对其他属性/目标的提及不充当本偏好的反证。无有效引用、只有标题提及或分母为零时 c=0。方向由多数明确倾向决定；平票为未知。这是规则置信权重，不是经概率校准的“正确概率”。

τ 只在 `{1,3}` 中开发选择。不能用历史评分直接把 c 设为高置信，也不能根据目标是否召回调整 c。需要分别报告短历史/较长历史分布及每层结果；层内人数不足时标为描述性，不能额外抽用户补齐。

### 5.4 证据质量融合

必要条件先沿用既有生产规则决定 eligible；Pending/Refuted/Conflict 不进入正式输出，高分不能补偿。

对于有依据的软偏好属性：目录语义映射中的 q=1 仅表示该字段来源已取得且引用有效，不代表商品质量；SIM 库存的 q 沿用已接受的覆盖、时效、一致性及 β=(.25,.5,.25)，无支持则 q=0；其他未知批次属性不能新增 q。模型只提出引用与解读，不得重写生产状态或 q。

最终分（已支持且匹配可观察的项才令 o=1，其余为 0）：

`s_ui = b_ui + λ Σ_d w_ud c_ud o_uid q_id (m_uid − b_ui)`。

λ∈{.25,.5,.75}。由于 Σw=1 且 λ,c,o,q,m,b∈[0,1]，这是先验 b 与有证据匹配的凸组合，分数仍在 [0,1]。未知或 c/q=0 时退回 b；弱历史、低质量证据只做较小调整，不把“缺值贡献零”直接变成强烈负面事实。完整分量、原始分与 round12 后排序分均保存；同分按 b 降序、parent_asin UTF-8 字节升序。

该公式不同于现有 `αb+(1−α)Σwqm`，属于本次新增算法候选，须经用户确认。未经过本轮证据的原论文公式不改写。

### 5.5 反馈与开发调参

核验者检查当前 Top-10、排序边界 8—15 位及采用的匹配/引用，对错误引用、把抱怨当喜好、越界事实、忽略当前请求等给出定位反馈。管理者据允许来源修订偏好、m 或引用，必要时调度受影响候选取证。q/四态只由生产核验器更新；程序重新排序，保留前后列表及原因。不能仅重写理由而标为排序反馈生效，也不能要求无问题时强行改名次。

无标签反馈不能使用 GT、HR/NDCG、用户目标排名、场景答案或模拟“用户确认喜欢”。每任务最多一次反思、两次 trial，不重跑直到命中。

开发选择分两段：先对同一开发面板 V00 保存不带反馈的 I1 特征前缀，以其来源验证通过的 w/m/c 所需统计做 λ×τ 六组**评分组件**比较；选择最高开发 NDCG@10，同分按 λ 较小、τ 较大。随后仅对所选参数实际执行完整 I1（三场景），其 Manager/Reflector 等受影响决策重新运行。组件网格不冒称六次完整系统实验；第一前缀的生成也计入 `budget.md`。所有试过的配置和成绩保留，选择后的开发区间不作独立确认性结论。

## 7 独立评价与有效性解释

独立评价进程读取原接受参考，不以生产 eligible、q 或 I1 分数造真值。兼容层保留实际 B0/I1/消融方法标识、完整 C 绑定及实际运行状态，禁止把新方法在报告中重命名为 M。原 `score_task` 目前只接受 R/S/M，新协议用独立入口适配并与既有指标样例对齐，不改旧协议文件或旧结果。

- 预先指定主指标：面板所有用户的 V00 端到端 `NDCG_P@10(I1−B0)`；HR@10 及 K=1,5 同时报告。候选未召回为 0，不筛成功用户。CB 和 R/S/M 的同面板差异单列。
- Q1/Q2 报真实偏好 HR/NDCG 及参考适用人群上的 SJ-NDCG、NA 数、资格违规、输出填充率、空列表及失败；SIM 质量结果不能替代 V00 真实偏好改善。
- 用户为配对重采样单位，预置 1,000 次、种子 1000；同一用户的场景先在用户内汇总。主比较报探索性 95%区间；四消融使用 98.75% 边际区间并报告各场景/人数，不选择有利 K。小面板、商品聚类与开发选择偏差全部披露。
- 已尝试且终结失败按既有口径计 0；not_started / unresolved / pipeline_error 分别报告，不凭空补成已观察结果。若不能取得全部计划用户终态，报告部分完成，不作“全用户验证完成”的结论；可另列固定全计划分母的保守下界并明确其非完整估计。
- 输出非法或必要条件违规为工程问题，先定位；不得丢掉这些行后计算漂亮成绩。合法完整 C 无合格项、D 无合格项、来源失败、预算中止分开。

判读事先固定：Δ≤0 为本轮未改善；Δ>0 但区间含 0 为正向点估计、证据不足；区间下界>0 仍只是所选开发面板的支持性证据。若 I1 胜 B0 但不胜同面板 CB，结论只能是“相对此适配基线改善，尚未超过内容基线”。只在 Q 场景变好、只降低失败或成本、只增加角色参与，均不足以宣布推荐算法成功。若两主方法成功子集差异与固定全部用户结果不同，两者一并披露。

## 8 参数 资源 失败与缓存

沿用 `4Router / https://4router.net/v1 / gpt-6-luna` 和既有生产发送能力。reasoning effort 与每角色 max_output_tokens 为显式可验证参数，先用至多 32 次真实业务形状开发调用核对 `low/medium` 及输出余量；不得默认为关闭推理，也不得将 1400 当新流程硬上限。具体角色额度、共享调用矩阵及选择规则见 `budget.md`。参数业务核对不是通用接入修复，不探测新渠道或价格接口。

单写入协调者、最多两个不同根任务在途，方法按用户交替顺序运行，避免时间/渠道状态集中影响某一方法。发送前原子登记意图与额度；成功、终结失败、未知回执不重发。关闭/禁止隐藏 SDK 自动重试。格式错误不自动追加修复调用；预算内下一 Manager 步仅可处理获准的协议观察，GT 永不进入。整个开发轮共享 24h 与新增 10GiB（含失败、评价、等待、源快照、临时与日志），到限终结并保留，不开启新额度。

缓存键覆盖实际可影响输出的模型/渠道/显式推理额、提示/Schema、H/请求、C/D/b、所见字段、快照/版本/权限/时点、观察、反馈、候选顺序及匹配/评分参数（当其进入决策时）。原请求字节完全相同才可复用模型结果；旧失败或未决不自动再发。
