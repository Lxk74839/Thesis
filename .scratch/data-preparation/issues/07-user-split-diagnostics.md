# 07: 报告用户样本流失并确认分组与旧数据复用

**What to build:** 按确认的资格规则诊断独立用户流失，并在确认分组及旧数据暴露政策后产出稳定的开发与测试用户划分。

**Blocked by:** 06：确认评论清洗、时间截断及用户资格规则

**Status:** ready-for-agent

- [ ] 逐阶段报告独立来源账户数、排除原因、历史深度、不同商品数、目标及商品覆盖和集中度。
- [ ] 区分账户层面的独立单位与无法验证的自然人独立性，披露共享商品、材料带来的相关性。
- [ ] 核查与已查看旧结果用户的重叠和暴露状态；未知状态明确记录，不能因重新生成文件就宣称全新盲测。
- [ ] 提出用户分组及复用政策的推荐、理由和影响，经确认后记录可复现的完整分组规则。
- [ ] 同一用户的全部根任务和场景保持同组；重复场景不增加独立用户计数；划分不得依据测试表现挑选。
- [ ] 通过公共入口验证分组稳定、同用户场景同组及未知暴露处理；产出仍标注为诊断或未冻结结果。

## 未决前置事项

确认 D5 的开发比例、精确哈希、盐、取整及旧数据暴露后的复用或排除政策；D10 的正式所需用户数仍由工单 12 论证。

## 执行约定

- 规格正文已确认，未决规则与参数尚未冻结。本次仅批准工单拆分；涉及的未决项须先完成明确的事实核查或用户决策，不得代填默认数值。
- 仅保留已确认的一个公共数据准备入口。数据功能实现按 TDD 逐个行为执行红、绿循环，通过入口验证外部结果；完成后按固定提交起点执行 Standards 与 Spec 代码审查，处理发现后提交。
- 项目依赖安装、代码运行、测试及构建显式使用 Thesis 专属环境；论文及原有研究材料只读，修改范围最小。
