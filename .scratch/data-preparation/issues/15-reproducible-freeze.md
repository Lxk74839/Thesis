# 15: 验证复现并冻结正式联合数据包

**What to build:** 在全量验收通过并确认冻结细节后，完成复现和独立复核，发布带完整版本、参数与摘要记录的正式联合数据包。

**Blocked by:** 14：实测完整数据并判定独立用户样本充分性

**Status:** ready-for-agent

- [ ] 区分原始来源、诊断产物与正式联合包；关键规则未确认、来源不完整、关联失败或样本充分性未通过时拒绝正式冻结。
- [ ] 记录来源摘要、范围与清洗规则、用户分组、SIM 与场景协议、比较及统计参数、随机种子、代码提交和实际环境依赖版本。
- [ ] 按确认的稳定序列化规则重跑，同来源和协议得到一致数据与语义摘要；获取时间等易变运行日志与稳定组件摘要区分。
- [ ] 独立复核覆盖正式对象关联、原始材料与登记事实、参考答案及隔离，方法和抽核选择提前确认并可审计。
- [ ] 发布组件版本、清单、SHA-256、规则结论和验收报告，明确 SIM 来源、真实评论归属与旧数据暴露状态。
- [ ] 所有产物与运行均遵守 Thesis 目录和环境约束；最终复核原论文及原研究材料摘要不变。

## 未决前置事项

确认 D12 剩余的稳定序列化、组件版本命名和独立抽核方法；所有正式包所使用的 D1—D12 子项须有明确结论，不能借本次工单批准自动冻结。

## 执行约定

- 规格正文已确认，未决规则与参数尚未冻结。本次仅批准工单拆分；涉及的未决项须先完成明确的事实核查或用户决策，不得代填默认数值。
- 仅保留已确认的一个公共数据准备入口。数据功能实现按 TDD 逐个行为执行红、绿循环，通过入口验证外部结果；完成后按固定提交起点执行 Standards 与 Spec 代码审查，处理发现后提交。
- 项目依赖安装、代码运行、测试及构建显式使用 Thesis 专属环境；论文及原有研究材料只读，修改范围最小。
