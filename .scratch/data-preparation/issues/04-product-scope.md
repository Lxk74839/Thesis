# 04: 审计商品范围并确认筛选与元数据冲突规则

**What to build:** 基于完整元数据提出商品范围和冲突处理的推荐方案，经用户确认后产出可逐商品追溯的目录及筛选审计。

**Blocked by:** 02：获取完整商品元数据并核查字段

**Status:** ready-for-agent

- [ ] 展示商品范围的推荐方案、理由、替代方案及其数量影响；对类别、标题、描述组合、排除项和模糊项给出明确规则。
- [ ] 筛选扫描完整元数据，目录选择不得由评论热度、模型表现或旧商品清单决定。
- [ ] 展示父商品重复元数据、字段冲突的实例和数量，经确认后按明确规则解决或记录排除。
- [ ] 每个纳入、排除或待裁决商品均有来源及理由；未解决的关键范围问题阻断正式目录。
- [ ] 公共入口夹具覆盖后段入选商品、歧义商品和冲突记录；确认记录与正式目录摘要可独立检查。

## 未决前置事项

先明确并确认 D1 的谷物与商品形态边界、模糊裁决规则，以及 D3 的父商品元数据冲突处理子项；不得默认纳入豆类、伪谷物或组合商品。

## 执行约定

- 规格正文已确认，未决规则与参数尚未冻结。本次仅批准工单拆分；涉及的未决项须先完成明确的事实核查或用户决策，不得代填默认数值。
- 仅保留已确认的一个公共数据准备入口。数据功能实现按 TDD 逐个行为执行红、绿循环，通过入口验证外部结果；完成后按固定提交起点执行 Standards 与 Spec 代码审查，处理发现后提交。
- 项目依赖安装、代码运行、测试及构建显式使用 Thesis 专属环境；论文及原有研究材料只读，修改范围最小。
