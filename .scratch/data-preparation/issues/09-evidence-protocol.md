# 09: 确认必要证据、SIM 基准及请求协议

**What to build:** 以入选父商品为对象，提出 SIM 基准、生命周期声明、必要证据及请求模板的推荐协议，经确认后形成可独立判读的正常与异常案例约定。

**Blocked by:** 04：审计商品范围并确认筛选与元数据冲突规则

**Status:** ready-for-agent

- [ ] 明确父商品、SIM 批次、事件、证据材料和登记记录的关联及粒度；真实评论始终属于父商品。
- [ ] 对每父商品一个基准批次的候选方案、必要证据组合及生命周期阶段给出推荐与理由，经确认后记录。
- [ ] 明确请求约束来源及构造规则；从历史推断与研究设计构造的请求分别披露，不能利用目标偏好标签设计请求。
- [ ] 明确证据的来源、授权、摘要、时间、版本、撤销及冲突语义，并用人工可核对的例子解释 Supported、Refuted、Pending、Conflict。
- [ ] 明确无法核验与有效否定的区别，给出独立参考如何由原始材料和登记事实判定的约定。
- [ ] 规则与案例经确认可供后续实现验证；尚未确认数值、证据强度及其他 D8 子项不默认填入。
