# 06: 确认评论清洗、时间截断及用户资格规则

**What to build:** 根据实际字段事实和流失诊断给出规则推荐，经用户确认后产出可复现的正式清洗视图及用户资格规则。

**Blocked by:** 05：提取全部匹配评论并诊断清洗影响

**Status:** ready-for-agent

- [ ] 逐项展示推荐规则、理由、替代方案及样本损失；已有论文数值只作为待审候选，不自动沿用。
- [ ] 明确去重键和文本归一化，区分重复与事实冲突；同商品等时评价不得任意选择最后一条。
- [ ] 明确全局时间截断、端点、缺失或异常时间对记录及用户资格的影响，并可由原始值复核。
- [ ] 历史严格早于目标时点；最新时点存在不同父商品的目标歧义时按确认规则处理；已见商品集合包含所有此前交互。
- [ ] 每步清洗有原因码、数量核对及来源追溯，原始提取保持不变。
- [ ] 公共入口覆盖低评分、空文本、重复、冲突、等时、未来历史及目标歧义；未确认规则产生明确待确认状态。

## 未决前置事项

确认 D2 的全局截断时点、端点及异常记录影响，D3 的评论归一化、去重、冲突及等时处理，D4 的正向评分、最少不同历史商品数和账户质量政策。

## 执行约定

- 规格正文已确认，未决规则与参数尚未冻结。本次仅批准工单拆分；涉及的未决项须先完成明确的事实核查或用户决策，不得代填默认数值。
- 仅保留已确认的一个公共数据准备入口。数据功能实现按 TDD 逐个行为执行红、绿循环，通过入口验证外部结果；完成后按固定提交起点执行 Standards 与 Spec 代码审查，处理发现后提交。
- 项目依赖安装、代码运行、测试及构建显式使用 Thesis 专属环境；论文及原有研究材料只读，修改范围最小。
