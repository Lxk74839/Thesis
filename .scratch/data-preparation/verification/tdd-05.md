# 工单 05 公共入口 TDD 留痕

公共测试接口继续为已确认的 prepare_data.py CLI。review_extract 是同一入口的阶段；内部模块和独立验收脚本不作为第二个公共数据准备接口。测试通过命令状态、机器报告及指明的外部产物观察行为，预期来自可人工核算的夹具。

输入为已验收目录及完整评论来源记录，输出包括字节保持不变的匹配评论、来源定位、全部入选商品的评论计数（含零）、去重／冲突分组及条件诊断。原始提取、候选诊断和正式清洗分别标记；本工单不发布正式清洗、模型输入或联合任务，也不判定样本充分。

运行与测试均显式 conda run -p Thesis；固定审查起点 b59611e97b6eedf07c4e624884c48570fbfa2cdd，工单开始提交 e2d94584f5f9c05b1a342259393c8813963c41f2。每个行为逐项先红后绿，以下按实际结果追加。

1. `-k test_extract_keeps_all`：红，CLI 不支持 review_extract。绿，同一入口增加阶段；逐行读至 EOF，只按 parent_asin 匹配，保持原始字节，低评分／空文本不删，零评论目录商品计数为 0，末尾匹配引用正确。
2. `-k test_extract_reports_duplicates`：红，缺少原始账户及重复诊断。绿，完整对象重复、原四元组重复与非键事实冲突分别统计；缺键不参与四元组归并，所有原始行和原组定位保留，未实施冲突合并。
3. `-k test_extract_diagnoses_nfc`：红，缺少归一化条件诊断。绿，NFC＋首尾空白候选与原文本分组分开，变体差异／其他非键字段仍按事实冲突报告；原始文本未改，候选 not_approved。
4. `-k test_extract_reaches_end`：红，坏 JSON 使扫描提前结束且没有完整扫描统计。绿，坏 JSON、非对象和无父标识分别定位，继续提取末尾匹配；无法证明坏源记录与入选商品无关时 extraction_incomplete，不宣称全部提取通过。
5. `-k test_extract_reports_single`：红，缺少质量和候选损失。绿，文本、评分、时间、标识单项诊断；完整对象归并、原四元组冲突隔离、NFC 条件安全归并分别及组合统计。每项保留评论、商品活跃集合、账户流失与源行原因；目录不因候选清洗而删除零评论商品。
6. `-k test_extract_history_uses`：红，缺少历史诊断。绿，按原始账户计数；严格早于最大有效时间的历史、不同商品、最新未见数及多父商品等时分别报告；低评分／空文本仍计入已见关系，未知时间不能建立可靠目标。
7. `-k test_extract_positive_candidate`：红，缺少文稿候选条件诊断。绿，只以文稿 ≥4 作为 not_approved 条件，最新不满足时不倒找正向旧记录；多目标、最新事实冲突、已见与不可靠时间各有原因；报告正向历史不同商品分布，minimum_prior_products 为 null，未选择门槛。
8. `-k test_extract_requires_verified`：红，未拒绝旧目录、单位变化、摘要变化、源数量变化或元数据关联变化。绿，只接受当前完整目录、完整 gzip 评论及同一元数据关联；实际摘要、目录集合、数量对账；同源同程序重跑 6 类产物摘要一致，同版本来源／实现改变须新版本。
9. `-k test_extract_equal_time`：红，不同正文导致相同商品等时冲突未被四元组发现。绿，另报告用户／父商品／时间组的全部事实差异；条件正向历史隔离冲突成员，独立隔离候选展示原始损失，不任意择一。
10. `-k test_extract_time_diagnosis`：红，缺少入选评论的原时值和 UTC 范围。绿，按已核实 epoch 毫秒转换，异常原值仍保留并单独诊断；不施加时间截断，cutoff_approval 为 not_approved。
