## Problem Statement

现有材料中的商品筛选依赖数据前缀，不能证明覆盖完整谷物商品范围；偏好任务与证据机制任务分别构造，不能直接拼接为联合实验。评论数量、候选数量和重复场景数量也不能证明独立用户样本充分。

本规格需要建立可复现的数据准备流程：完整选取商品及对应评论，明确商品与模拟供应链对象的关系，以用户为单位判断样本充分性，并生成两模块共用、模型输入与评价标签隔离的实验数据包。旧数据及结果保留为探索或回归材料，不作为新数据规格已达标的依据。

## Solution

由一个公共入口按阶段接收来源清单、可读取的数据源、该阶段已确认的数据协议和项目内输出位置，生成原始获取结果、诊断产物或正式联合数据包及验收报告。入口内部完成筛选、清洗、用户任务构造、模拟材料构造、关联检查、标签隔离和复现记录，不新增面向使用者的分散准备接口。

联合数据包包含商品、评论、模拟批次、事件、证据材料、登记与版本记录，以及两模块共用的根任务和配对场景。接口的实际命令名称与参数形式在实施时确定，不在本草案中虚构可运行命令。

原料、目录和诊断结果可以分阶段留档；正式联合实验版本必须通过适用门禁。协议未确认、来源不完整、关联或隔离失败、样本不足时，入口输出明确状态与原因，不发布为正式可用联合实验数据。

## User Stories

1. 作为研究者，我希望扫描完整商品元数据，以便避免把文件前缀当成完整商品范围。
2. 作为研究者，我希望预先确认谷物定义及排除规则，以便筛选结果不随实验效果变化。
3. 作为研究者，我希望保留入选商品的完整原始元数据，以便审计筛选依据和缺失字段。
4. 作为研究者，我希望提取全部入选商品评论，以便覆盖不同评分、时间和用户。
5. 作为研究者，我希望看到去重、异常记录及数量对账，以便判断清洗是否改变研究对象。
6. 作为研究者，我希望保留原始时间并验证转换方式，以便严格区分历史与未来。
7. 作为研究者，我希望评论始终关联父商品，以便不把模拟批次冒充真实购买批次。
8. 作为研究者，我希望批次、事件、材料和登记记录有一致对象标识，以便追溯证据链。
9. 作为研究者，我希望模拟来源明确标注，以便限定实验结论。
10. 作为实验设计者，我希望两模块使用相同根任务，以便进行统一联合评价。
11. 作为实验设计者，我希望请求和约束的来源可辨认，以便区分历史偏好与实验设计要求。
12. 作为实验设计者，我希望固定完整未见商品候选集，以便不同方法可比较。
13. 作为实验设计者，我希望固定材料快照、访问范围和预算，以便控制比较条件。
14. 作为评估者，我希望按唯一用户账户计数，以便重复评论和场景不增加样本量。
15. 作为评估者，我希望看到历史商品数及样本流失原因，以便识别用户历史不足。
16. 作为评估者，我希望预先确定样本充分性的判断方法，以便避免事后以结果决定样本量。
17. 作为研究者，我希望样本不足时停止正式实验发布，以便不夸大证据强度。
18. 作为评估者，我希望同一用户始终属于同一数据组，以便避免跨组泄漏。
19. 作为评估者，我希望历史记录严格早于目标，以便检验未来预测行为。
20. 作为评估者，我希望背景统计也遵守时间边界，以便避免其他用户的未来信息泄漏。
21. 作为模型使用者，我希望只收到允许的任务输入，以便评价答案不进入推荐过程。
22. 作为评估者，我希望目标标签和证据参考答案独立保存，以便分别评价偏好与证据合规。
23. 作为实验设计者，我希望按固定协议构造正常和异常材料，以便比较证据处理能力。
24. 作为实验设计者，我希望扰动与目标标签无关，以便场景不暗示正确推荐。
25. 作为评估者，我希望无关材料变化作为对照，以便区分必要证据变化与一般输入扰动。
26. 作为评估者，我希望用独立参考规则验收，以便避免生产核验器给自己生成答案。
27. 作为复现者，我希望获得参数、版本、摘要和数量清单，以便复现相同数据版本。
28. 作为项目维护者，我希望所有产物位于项目内且使用 Thesis 环境，以便保持原材料只读及运行隔离。

## Implementation Decisions

### 1. 数据包内容与发布状态

| 组成 | 必须包含 |
|---|---|
| 来源与协议 | 来源身份、获取时间、原文件摘要、字段解释、所有已确认规则和参数 |
| 商品目录 | 全量筛选记录、入选父商品、原始元数据、模型可见字段、排除与待审原因 |
| 评论集合 | 入选商品全部原始评论、去重分组、清洗结果、时间与关联状态、用途标记 |
| 用户与划分 | 受限身份映射、稳定用户标识、资格判断、开发／测试归属、历史与目标划分 |
| 模拟供应链 | SIM 批次、生命周期事件、原始材料、声明对象、权限、登记、版本与撤销记录 |
| 共用实验任务 | 根任务、固定候选、请求、快照、查询范围、预算配置、场景分配与方法比较条件 |
| 私有评价数据 | 留出目标、参考证据状态、候选合格集合、场景生成记录和参考答案依据 |
| 验收与复现 | 来源对账、对象／时间／隔离检查、样本充分性报告、组件版本、输出摘要与冻结记录 |

“数据结构通过”“样本充分性通过”和“正式联合版本冻结”分别记录。未测量或缺少已批准判定规则时记为待判定，不能记为通过。诊断或探索产物必须携带未通过原因。

### 2. 完整元数据筛选

- 扫描所选 Grocery 来源的完整商品元数据，达到文件结束并完成解压与解析对账。禁止按前若干行或文件前缀代替全量扫描。
- 在查看目标表现前冻结谷物范围、商品形态、类别／标题／描述的判断规则、排除词与冲突处理优先级。旧规则包含扁豆、鹰嘴豆和干豆，不能未经确认直接沿用为新谷物范围；伪谷物是否纳入也须确认。
- 筛选依据来自元数据，不根据评论活跃度、任务数量、评分高低或模型效果反向选择商品。模糊商品进入待审集合；人工裁决须记录依据并纳入协议版本。
- 入选商品即使没有可用于任务的评论，也保留在目录与统计中。保留完整原始对象、来源定位及字段缺失状态；“完整”不意味着凭空补齐缺失字段。
- 同一父商品的重复元数据保留来源记录；完全重复可以归并，实质冲突按经确认规则处理，未解决的关键冲突不得进入正式目录。

### 3. 全部评论提取、去重及时间截断

- 冻结入选父商品集合后，扫描完整评论来源，提取所有匹配父商品的评论。保留低评分、空文本和缺失字段记录及其状态；任务资格过滤不得替代全评论提取。
- 保留原始用户标识、父商品／变体标识、评分、标题、正文、原时间、来源定位与可用来源字段。变体标识不能当作批次标识，也不允许把其他父商品评论补入。
- 文稿已有的“用户、父商品、时间、文本”四元组作为去重分组方案。原始组成员与清洗结果均可追溯；文本归一化及评分等事实字段冲突的合并规则待确认。冲突组不得通过任取一条或取最高评分消解。
- 原始时间与归一化时间同时保留。先核查实际字段、单位和时区，再采用统一时间尺度；禁止仅凭数值大小猜测单位。
- 全局评论截断时点及端点规则待确认。截断后的记录保留在原料审计范围，但不得用于该版本任务或历史统计。
- 解析失败、缺失关联键和异常时间必须对账并隔离。无法解析且无法证明与入选商品无关的源记录，会阻断完整性验收；不能默默跳过后仍声称全部提取完成。

父商品关联依据来自来源字段定义，但实际文件字段仍须实测核对。[Amazon Reviews 2023 官方说明](https://amazon-reviews-2023.github.io/main.html)

### 4. 商品、批次、事件及材料关联

- 真实评论的唯一业务归属是父商品。真实评论没有模拟批次真实评价标签，也不能根据评分或文本推断真实购买批次。
- 首版采用材料提出的“每个入选父商品一个 SIM 基准批次”方案；本草案审核时确认是否沿用。候选身份由父商品与模拟批次共同确定。
- 模拟批次必须指向一个已入选父商品；事件指向批次；材料指向相关商品、批次、事件及其支持／否定的声明。登记记录、版本、摘要和查询返回必须采用相同对象关系。
- 生命周期覆盖采收、包装、储存、检验、运输、零售。各阶段时间、材料要求和有效期由确认协议决定，不补造未经论证的日期或时长。
- 同一批次在配对场景中保留业务身份，以独立场景实例和快照版本区分材料状态，不能把复制场景计为新用户或新的真实批次样本。
- 真实元数据中的商家陈述仍是来源陈述；它不会自动成为已核验供应链事实。模拟材料全部标明 SIM，实验结论限定于模拟证据链及声明范围。

### 5. 用户、历史、目标与候选

- 以来源唯一用户标识作为可观测的用户账户单位，使用稳定映射关联所有评论、任务与场景。账户数量不等于已证明相互独立的自然人数；账户质量及疑似重复账户处理规则待确认。
- 沿用文稿的留后方案作为草案：先确定用户有效互动的最大时间，再判断该时点能否形成唯一父商品目标；不能向前寻找更早的正向评论来替代不合格的最新目标。
- 最大时间对应多个父商品时，按文稿方案排除该用户的正式任务并记录原因。单父商品但多条评价冲突时，按待确认规则处理，不以文件行序选择答案。
- 目标须属于入选目录、符合正向门槛且在更早历史中未出现；画像所需历史为严格早于目标的正向有效文本记录。正向门槛及最少不同历史商品要求见待确认表。
- 判断“未见商品”时检查全部更早有效互动，包括低评分和空文本记录；不能只检查进入画像的正向评论。无法可靠确定历史、目标或未见关系的任务不发布。
- 同一用户及全部场景只能进入同一组。开发／测试划分采用冻结的用户级确定性规则，具体比例、哈希规则、盐及取整方法待确认。
- 候选为目录中该用户此前未见的全部父商品及对应 SIM 批次，顺序固定且不依据目标标签。目标父商品可自然出现在候选中，但输入不标明哪个候选是目标；不采用随机负采样来替代完整候选评价。[关于采样推荐指标的研究](https://research.google/pubs/on-sampled-metrics-for-item-recommendation/)
- 目标正向门槛会限定研究人群：结论针对符合规则的评论用户，未观察到的互动不能自动标为负向。

### 6. 时间与输入／标签隔离

- 区分真实互动时间和模拟材料核验时间。两者分别记录；模拟场景不被描述成真实用户购买时的供应链状况。
- 背景互动统计排除所有开发／测试用户，并严格使用任务目标时点之前的记录。任何利用互动训练的特征或表示也要遵守任务可见时间，不能仅在候选阶段删除未来商品。[推荐评估中的时间泄漏研究](https://arxiv.org/html/2010.11060v4)
- 商品元数据视为来源采集时的静态快照，明确该实验属于回顾性任务，不能宣称已恢复每个历史时点的商品信息。聚合评分、评论总数和采集时价格不作为历史偏好输入。
- 模型只接收明确白名单字段、允许的历史记录、请求、候选及工具访问。正文、详情等自由文本字段须审计后才能加入白名单；不能把完整原始元数据直接送入模型。
- 完整原始评论中包含留出目标，因此原始评论库不能作为模型可浏览语料。留出目标标识、目标评论文本／评分、合格集合、扰动计划和参考答案只对准备／评估侧开放。
- 按请求与权限可访问的供应链材料可通过工具暴露；答案标记、可读场景类型、暗示结果的文件名、错误标签、排序和调试说明不得暴露。SIM 标记用于来源披露，不代表合格答案。
- 隔离必须由显式输入构造及受限读取落实，不能只依赖提示词要求模型“忽略标签”。验收检查实际载荷和可访问对象，而非仅检查目录名称。

### 7. 两模块共用的实验任务

每个合格用户形成一个偏好根任务。根任务冻结：用户标识、允许历史、原始请求与结构化约束、目录版本、完整候选及顺序、基础分数及其生成版本、输出规模、材料快照、查询范围、核验时点、权限、协议版本和场景分配规则。

供应链约束属于实验设计要求，须与历史文本推断的偏好区分，不能声称真实用户曾提出这些约束；请求生成不得读取目标评论或目标商品标签。

强规则、单智能体、六角色及相关消融共享根任务和可获得的信息范围。配对场景仅改变预先指定的材料条件，历史、候选、请求与基础分数保持一致。正式比较前须通过适用技术验证并冻结可执行预算及其重试、失败计量、截止和发布配置；工单12的候选预算及验证门冻结不满足执行条件，未确认或未验证的执行值不能默认填零。

生命周期追溯与推荐依据核验针对任务指定的 SIM 候选和材料快照工作；偏好评价仍针对真实父商品。真实目标评论只提供父商品偏好标签，不提供模拟批次的真实质量标签。联合评价通过“父商品偏好目标＋独立 SIM 合格集合”连接两模块。

无合格候选时允许合法空结果，不能用偏好高分替代缺失必要证据。实验任务同时记录空结果、未完成、超时、失败、重试及成本，不通过删除失败任务改善结果。

### 8. 正常与异常证据场景

先冻结正常 SIM 材料、必要声明、最小材料组合、登记历史和权限，再按独立种子及预先批准的对象选择规则生成扰动。生成器只能读取允许的目录、模拟材料和协议，不读取私有偏好目标、目标评分／文本或模型输出；不得专门针对目标商品制造成功或失败。

材料可采信检查覆盖来源与权限、摘要、对象／事件关联、时间、登记与版本。参考答案只针对已声明且授权可见的材料范围，不将登记完整性解释为真实供应链完整性。

| 场景 | 构造规则与独立参考要求 |
|---|---|
| 正常 | 必要声明具有满足协议的有效材料组合；只有所有必要声明获支持时，候选才合格 |
| 缺失 | 移除协议指定的必要材料；剩余材料不能完成支持时为 Pending，不等于商品质量差 |
| 对象错配 | 材料指向其他商品、批次或事件；不计为当前对象证据，再依据剩余有效材料判断 |
| 摘要／登记异常 | 改动内容或登记关系造成不一致；受影响材料不可采信，不自动构成否定证据 |
| 有效否定 | 加入可采信且明确否定必要声明的材料；仅有有效否定时为 Refuted |
| 有效冲突 | 同一声明同时存在有效支持和有效否定，且无法按版本规则消解时为 Conflict |
| 过期／撤销 | 在固定核验时点使材料无效；该材料不计，剩余材料不足时为 Pending |
| 新版本 | 按固定登记历史改变可见版本；依据新版本事实重算，不假定更新必然改善合格状态 |
| 权限不足 | 材料不可授权访问；按可见集合判定，不把无权读取解释为材料内容否定 |
| 无关变化对照 | 只改变与必要声明无关的内容；必要声明状态及候选合格集合应保持不变 |

声明状态采用 Supported、Refuted、Pending、Conflict。候选有必要声明冲突则为 Conflict，否则有否定则为 Refuted，全部必要声明获支持才为 Supported，其余为 Pending；没有必要约束的任务按协议记录为不适用必要证据筛选。

场景构造沿用工单11已接受版本；原8必要视图各1/8、Q1/Q2各1/2、主重复r=1按工单12 F1—F3确认生效。两臂分别汇总，不混成10视图平均；未被具体确认覆盖的新增场景或参数仍待确认。扰动计划保存在评价侧；模型看到实际材料及允许的核验结果，不看到设计答案。

### 9. 独立用户样本充分性

资格判断与充分性判断分开。入口必须报告全量目录／评论数、唯一账户数、时间有效账户数、唯一目标账户数、目标正向且未见账户数、历史达标账户数及最终开发／测试账户数；每步给出排除原因。并报告不同历史商品数、正负互动、有效文本数、目标集中度、类别及时间覆盖。

独立样本数为符合规则的唯一用户账户数。开发与测试分别计数；同一账户的多条评论、多个候选、正常／异常场景、重复运行均不增加独立用户数。每用户只有一个偏好根任务；场景和重复先按冻结权重在用户内汇总，再做用户级比较。

样本充分性通过必须同时满足：

1. 完整来源扫描及用户资格规则已经通过验收。
2. 主要研究问题、主要比较、指标／输出规模、适用用户范围已预先确定。
3. 按事先确认的精度目标，或有依据的效应与功效设计，确定所需用户数及计算方法；方差依据只能来自可论证界限、独立先验或开发／先导数据，不能依据测试集赢家反推。
4. 实测合格测试用户数达到预定所需数；指标不适用的用户不得伪装为有效样本。
5. 经确认的历史充分性、覆盖与集中度要求得到满足；报告适用范围，不以总体评论数替代。

缺少上述规则或尚未测量记为“待判定”；规则冻结后实测不达标记为“样本不足”；全部适用条件满足才记为“通过”。本草案不设未经论证的用户数下限。

共享商品、材料和运行故障可能使用户结果相关。记录这些共享关系，统计结论限定于冻结目录及场景设计；目标父商品整簇bootstrap、逐簇删除、目标集中度/历史/类别/年份等描述性敏感性按工单12已确认正文第8节执行。账户为主要配对单位，不能仅凭不同用户标识声称已经证明完全统计独立，也不将上述敏感性当成全部交叉依赖修正。

不足时先核对全量提取、关联、时间和清洗造成的样本流失，再提交缺口报告。后续由用户确认扩大商品范围或收窄为机制验证／探索研究，并产生新协议版本。禁止补造用户、增加重复场景、按结果放松筛选、重分组挑选有利划分，或自动扩到其他食品。

### 10. 独立验收与评价

参考依据来自批准规格、可人工核算的微型夹具和独立参考生成过程。参考过程读取原始材料、冻结登记历史、权限及必要声明规则，独立得出声明状态与候选合格集合；不调用待评估模型，不复用生产核验器的最终状态，也不把“计划制造的异常类型”直接当作最终答案。

偏好目标与证据合格性分别保存和评价。受约束排序的理想增益为零时，指标记为不适用并报告用户数；不能记为零或悄悄删除。预先确定各指标的适用用户集合，不能按方法成功与否筛选比较用户；失败与合法空结果分别报告。

| 验收门禁 | 通过条件 |
|---|---|
| 来源完整性 | 全量读取结束、解压完整性及解析对账通过，无未解释的截断或记录损失 |
| 筛选与评论 | 每项筛选可追溯；入选父商品全部匹配评论有去向；去重及排除数量可对账 |
| 对象关联 | 正式包中关联键一致、无孤立引用；评论仍只归属父商品 |
| 时间与分组 | 无等时／未来历史，无用户跨组；背景及互动训练遵守时间限制 |
| 输入隔离 | 实际模型载荷和可访问材料不包含私有目标、答案或场景提示 |
| 场景参考 | 从有效原始材料与登记状态独立推导；无关变化对照保持预期不变 |
| 样本充分性 | 按已批准方法判定通过，而非仅有若干可运行任务 |
| 复现与冻结 | 参数齐全、版本及摘要完整，同源同协议重跑产生相同语义数据与稳定摘要 |

原始异常可以保留在隔离区并对账；正式包不能遗留未解决的关键异常。抽查不能替代对全部正式记录的关联、时间与隔离检查。摘要一致只证明内容一致性，不能证明原始事实真实。

### 11. 可复现参数、版本和摘要

记录来源网址及身份、获取时间、文件字节数与 SHA-256、全量扫描数量、解压／解析状态、源记录定位、筛选及去重规则、时间映射与截断、用户划分、场景协议、所有随机种子及随机算法版本。

同时记录协议、目录、评论、任务、SIM 材料、参考答案和验收程序的组件版本与摘要，以及 Thesis 运行时、依赖版本和代码版本。Git 尚未建立时如实记录版本追踪方式，不能填写不存在的提交。

冻结清单保存各组件之间的版本依赖和摘要，不用包含自身摘要的内容递归计算自身摘要。稳定数据序列化与排序规则须明确；运行日志时间等易变信息与稳定数据分开。相同原料、协议和运行版本应产生相同语义记录及稳定数据摘要，不要求带有运行时间的日志或压缩包装逐字节相同。

任何筛选裁决、清洗规则、划分、场景或参考规则变更都产生可追溯的新版本。已有正式版本不可手改而不更新版本；身份映射和私有标签不因复现要求向模型公开。

## Testing Decisions

只通过已确认的公共准备入口验证外部结果：产物、状态、数量、关联、访问范围及复现摘要。覆盖目录筛选、全评论提取、去重与时间处理、用户任务、模拟材料、独立参考、隔离和充分性判定。

微型夹具必须覆盖：

- 文件后段才出现的入选商品／评论；零评论商品；低评分、空文本、重复与冲突记录。
- 缺失父商品、时间单位映射、等时与未来历史、最新目标歧义、已见目标。
- 用户分组稳定性、所有场景同组、未来背景记录和评价用户排除。
- 候选完整性及顺序；目标标签、聚合字段和场景提示无法进入模型可访问输入。
- 正常、缺失、错配、有效否定、冲突、过期、撤销、新版本、权限及无关变化。
- 增加重复场景后独立用户数不变；充分性待判定／不足时不生成正式通过版本。
- 不完整来源、未解决关键规则和关联失败产生明确诊断；同源同协议重跑摘要一致。

夹具中的模拟账户只用于接口测试，不能计入真实数据样本。正式验收另需完整真实来源扫描、用户数量实测、充分性判断和联合包检查，不能以夹具通过代替。

旧协议测试已有防等时／未来历史、防目标及聚合特征泄漏、完整未见候选、时间受限背景统计、排名指标及配对重采样等行为，可作为验收参照；本轮只读审阅，没有运行这些测试，也不把旧实现的正确性视为新流程已验证。
