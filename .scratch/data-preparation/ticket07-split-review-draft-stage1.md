## 1. 推荐与理由

**推荐A：保留全部1,603账号，把旧资格探索集合中重叠的16个全部放开发，随后按固定哈希补足320个开发账号，余下1,283个为测试池。**

推荐不建立在模型性能、目标命中或最优覆盖上。没有比较多个盐或种子；只为政策影响试算下述一个固定候选盐。D10尚未确定所需账号数，不能以本表人数断言样本充分。

## 3. 拟冻结的精确规则

以下每一项均是待批准草案，未写入 `config/`、`records/` 或公共准备入口。

### 3.1 输入与单位

1. 输入固定为06清洗主记录及其验收清单、格式勘误所绑定的组件；仅 `status == "qualified"` 的来源唯一 `user_id` 构成集合Q，当前 `|Q|=1603`。
2. `user_id`使用JSON解码得到的原始字符串，UTF-8编码；不trim、不变大小写、不做Unicode归一化、不使用文件行号或Python内置`hash()`。空值／非字符串或重复资格身份属于验收错误，不自动补造标识。
3. 一账号只有一个根任务。后续根任务、所有配对场景、重复运行均通过受限身份映射继承同一账号组别；场景ID、批次、候选、目标、模型表现不参与划分。

### 3.2 精确哈希、盐和排序

候选公共盐为下列**单行ASCII字符串，无引号、空格或换行**：

```text
Thesis-ticket07-grain-A-1.1.15-review-cleaning-1.0.0-split-v1
```

对账号u：

```python
uid_bytes = user_id.encode("utf-8")
digest = hashlib.sha256(salt.encode("utf-8") + b"\x00" + uid_bytes).digest()
sort_key = (digest, uid_bytes)
```

用完整32字节摘要作无符号字节字典升序，不截断、不取模；摘要相同时按原标识UTF-8字节升序解决并列。等价的完整小写64字符十六进制排序也须保持此规则。排序不依赖操作系统区域设置、文件行序或线程调度。

盐用于明确版本与确定排序，**不提供匿名化或保密性保证**。身份映射与任何正式分组明细仍须留在受限准备／评价侧，不向模型公开。

可手工核对的合成测试向量：`user_id = "fixture-user-001"` 时，摘要为 `c0b0f92cdb739fb58f60dd59087228d311af1b4e1d65f8aad86b6b503b86dc90`。该标识只是算法夹具，不是数据样本。

### 3.4 取整与分配

**A推荐算法：**

1. 总池Q，不排除账号；开发名额D=`len(Q)//5`，即精确floor(N／5)，不用四舍五入、银行家舍入或逐账号20%阈值。
2. 先把E中的16个放开发，剩余名额为304。
3. 对Q\E按3.2排序，前304个补入开发；余下1,283个为测试。
4. 若未来同一政策下限制开发集合数量超过D，停止分组并报告冲突，不能静默增大开发比例或把暴露账号放回测试。当前16≤320。

**B／D：**先从Q分别排除E／Q∩R7538；以剩余集合P为分母，D=`len(P)//5`，按同一哈希排序取前D开发，其余测试。不能把排除前的320名额沿用到排除后的池。

## 4. 冻结后的使用约束

- 开发集用于模型、提示词、规则参数与预算选择；测试配置冻结后统一运行。失败、超时、合法空结果及指标不适用按后续协议记录，不按性能删除账号或替换分组。
- 本次已经查看目标分布汇总，所有方案均披露这一事实。禁止比较不同盐、重抽划分或按未来测试赢家选择组别。
- 后续不能按场景是否成功重新分配账号。新建任何场景必须查询根账号所属组，未知账号或跨组冲突应阻断产出。
- 统计以账号为单位。场景与重复先在账号内按另行批准的权重汇总；场景总数、候选总数和调用次数不作为独立样本数。
- 若冻结后发现新的测试结果阅读暴露，保留原归属与审计记录，暂停受影响正式比较并报告；是否排除、降格为探索或更换版本由用户确认。不得根据表现移动账号、补抽有利账号或自动换盐。
